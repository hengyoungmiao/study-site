# 高等数学知识网页

按同济第八版上册排：一章分成各小节，最后是章末考研难度提升。每一小节有三栏：知识点、题型梳理、易错点。

## 文件

| 文件 | 作用 | 以后改不改 |
|---|---|---|
| `index.html` | 页面框架（Drive 备份里叫 `高等数学.html`，双击用浏览器打开，不联网也能用） | 只在加数据文件或改功能时改 |
| `数据/第N章-第M节.js` | 一节的全部内容：知识框架、知识点、题型卡、易错点 | 每节新建一个 |
| `数据/第N章-章末.js` | 章末考研难度提升：全章思维导图、题型板块、混合自测 | 每章一个 |
| `数据/我的总结.js` | 预置的「✎ 总结」 | 恆口述总结时加 |
| `工具/lint.js` | 公式和加粗检查脚本 | 不改 |
| `依赖/` | 公式排版用的 KaTeX 0.16.11，字体已内嵌 | 不改 |

线上版本由 Cloudflare 从 GitHub `main` 分支自动部署；Drive `进度库/交互网页/高等数学/` 是备份。旧的 Artifact 版本已停用，不再更新。

## 加一节

1. 恆刷完苏大题集本节后，在科目项目里说「出 1.2 的知识网页」，得到 `数据/第1章-第2节.js`，放进 `数据/`。
2. 打开 `index.html`，找到 `const DATA_FILES = [`，加一行 `"数据/第1章-第2节.js",`。
3. 跑 `工具/lint.js`，`problems 0` 后提交到 `main`、推送，再同步到 Drive 备份（见最后一节「发布流程」）。
4. 同样内容的 Markdown 版新建到收件箱 `进度库/收件箱/科目项目/高等数学-YYYY-MM-DD-<节号>题型卡.md`，最后留一栏「我的补充」；克在日复盘时并进 `进度库/学习档案/题型卡/高等数学-第N章.md`。

数据文件的写法照 `数据/第1章-第1节.js` 抄：`KB.add({ id, chapter, title, pages, sources, framework, points, types, pitfalls })`。章末用 `KB.addChapterEnd({ chapter, ... })`，字段相同。

- `framework`：`main` 一句话主线；`nodes` 关系图的概念，7–8 个就够（`col` 列、`row` 行、`kind` 是 map / func / prop / build）；`edges` 箭头（`from`、`to`、`label` 写在箭头上的几个字）；`keys` 3–5 条要点（`q` 复习时的问题、`a` 页面上显示的要点）。不放自测按钮和长清单。
- `types` 每张卡：`signal` 看到、`example` 例题、`idea` 这类题的通法（`key` 一句话概括、`how` 通用步骤，不针对例题；`refs` 辅导书原话，每条带出处）、`first` 第一步、`steps` 解答、`pitfall` 易错、`practice` 练习。题型卡不放「我的补充」。
- `pitfalls` 每条：`wrong` 错误想法、`test` 陷阱小题、`ans` 答案、`why` 为什么错、`right` 正确做法、`link` 关联的题型或关系。
- 小节里不放考研增量；考研内容只放章末。

### 点击跳转（2026-10-19 起）

- 关系图的每个 `nodes` 项和思维导图的每个节点都可以写 `go`，点了就跳到对应内容并闪一下：
  - `"p3"` 本页知识点、`"t2"` 本页题型、`"e4"` 本页第 4 条易错点、`"m2"` 本页混合自测第 2 题、`"b3"` 章末的板块（筛出这一板块的题型卡）；
  - `"1.3"` 跳到别的节；`"1.3:p5"` 跳到别的节的某一条。网址也能这样写：`#1.3:p5`。
- 章末多三个字段：
  - `mindmap`：全章思维导图，`{ title, main, root, go, branches: [{ label, go, kids: [...] }] }`，可以多层嵌套。手机上自动变成竖排的大纲树。
  - `blocks`：题型板块 `[{ id: "b1", name: "① 函数性态" }]`；每张题型卡写 `block: "b1"`，题型页顶部出现板块筛选。
  - `sectionLinks`（只用于章末）：`{ "1.6": ["t11","t16"] }`，章末题型和小节互相跳转。
  - `mixed`：混合自测，每题 `{ id, block, level, q, src, hint, ans, go }`，页面上多一个「混合自测」标签，按钮依次是看思路、看答案、对应题型。

## 换成别的科目

复制整个文件夹，改 `index.html` 里的 `CATALOG`（目录和页码）、标题和 `STORE_KEY`，再换数据文件。

## 复习和记录

右上角「复习」把知识点、要点、题型、易错点混在一起抽查：答错的本轮再出现，直到全部答对一次；一次答对的按 1、3、7、21 天往后排，答错过的第二天再来。

自评、☆ △、总结和复习安排先存在本机浏览器，填了 GitHub 令牌后自动同步到 `records` 分支（见下文）。没填令牌时，可以点右上角「记录」→「复制记录」手动备份，换设备时粘贴导入，会自动合并。


## 星号、自评、复习中心、搜索（2026-10-19 加）

- 知识点、题型、易错点、混合题、思维导图节点旁都有 ☆、△ 和 ✓ ✗ 自评，记录键 `节号/条目号`（导图节点 `节号/mm:名称`）。☆ 是「不熟」，△ 是「重点记录的内容」，两个都是开关、只能手动点掉（△ 存在 `stars` 里，键后加 `!`）；✓ ✗ 是做题结果，最近一次是 ✗ 的条目进「薄弱清单」，重新自评 ✓ 后离开。旧记录里的 △ 自评不再显示。
- `#review` 复习中心：`#weak` 薄弱清单、`#quick` 速认、`#sample` 限时抽题、`#spaced` 间隔复习；`#search:关键词` 全站搜索；章末页导图有「闭卷」开关。

## 记录存到 GitHub 和错题区

- 自评、☆、△、我的总结自动提交到本仓库的 `records` 分支（`records/state.json`），不影响网站；手机和电脑共用，也方便复盘。网页直接调用 GitHub API，不需要服务器。
- 每台设备在页面「记录」里填一次 GitHub 令牌（只存在本机浏览器）。建法：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token；Repository access 选 Only select repositories → `study-site`；Permissions → Repository permissions → Contents 选 Read and write；有效期可以选一年。
- 合并规则：自评按「日期+结果」取并集，复习间隔取 `last` 较新的，☆ △ 和总结按操作时间取较新的（删除留空值作标记）；改动后约 4 秒自动提交，离开页面时立即提交。
- 我的总结：知识点、题型、易错点、混合题的每个块下面有「✎ 总结」按钮，点开写自己的话，自动保存。预置的总结写在 `数据/我的总结.js`（`KB.seedNotes({"节号/条目号": "文字"})`），只在设备上还没有这条时写入。
- 错题区 `#wrong[:编号]`：题目在 `records/wrong.json`（数组，每题 `{ id, created, chapter, section, type_key, source, cause, data }`；`cause` 用审题/概念不清/条件遗漏/方法选择/计算/书写表达；`data` 是 `{ title, stem, mine, key, ans, variant, links }`，`links` 是对应的知识点和题型，如 `["1.5/p7","1.5/t5","1.5/e2"]`（p 知识点、t 题型、e 易错点、m 混合题，不写就用 `type_key`）），由克整理后提交。错题的自评键是 `w/编号`。

- 侧边栏目录：当前小节（含章末页）下面自动生成可折叠的「本节大纲」（知识框架、知识点、题型梳理、易错点、混合自测），点条目直接跳到对应内容；各组的展开状态记在本机浏览器里。数据文件不用改。

- ✓ ✗ 可取消：今天最后一次自评是哪个，那个按钮就高亮；再点一次高亮的按钮，撤销这一次自评。

- 手机（宽度 900 以下）的目录是从左边滑出的抽屉：点顶部「目录」打开；点遮罩、点 ✕、在抽屉里往左滑、按 Esc、点目录里的小节都会收起。点本节大纲的条目也会收起并跳到那一条。

- 错题索引：错题卡下面列出对应的知识点、题型，点了直接跳过去；反过来，知识点、题型、易错点、混合题的块下面会出现「错题 n」小标签，点了跳到那道错题。

## 多端同步和复盘（2026-10-19）

- 每台设备（电脑、平板、手机）填同一个 GitHub 令牌后，记录自动合并：页面打开时拉取、改动后约 4 秒提交、离开页面时立即提交、开着页面时每 90 秒拉一次，所以各端进度一致。
- 快捷配置新设备：打开 `网址/gaoshu/#setup=令牌`，令牌存进这台设备并立刻同步，地址栏里的令牌会被清掉。令牌只放在 `#` 后面，不会发给任何服务器；但链接本身要妥善保管，别发到群里。
- 撤销自评会记一条「已撤销」（`state.json` 里的 `del`），不会被另一台设备的旧数据复活。
- `records/review.md`：每次同步后自动更新的复盘摘要（今天做对和不会的、最近 7 天、最近一次是 ✗ 的、☆ △、到期复习、我的总结），条目名都已翻译成知识点和题型名。克复盘时读它；原始数据是 `records/state.json`，每次改动在 `records` 分支都有一条提交，可以看历史。
- 克读取方法：`git fetch origin records`，再 `git show origin/records:records/review.md`。

## 建站与维护规则（2026-10-20 补）

### 一、内容规则（出每一节都遵守）

- 出一节前，先把教材本节、习题全解、吉米多维奇「基本题型」、张宇基础30讲、强化书（18讲、9讲、武忠祥、李永乐）、1000 题都检索整理过，再总结题型（JC-0022）。
- 一节四块：知识框架、知识点、题型卡、易错点；章末只放考研提升。
- 知识框架：一句话主线 + 一张少而清楚的关系图（7–8 个概念，箭头上写关系的几个字）+ 3–5 条要点；不放自测按钮，不列长清单；小节里不放「教材没讲、考研书多讲的」，成块的考研内容只放章末。
- 知识点：定义、定理（条件写全）、结论、公式，每条附页码和一个自测问题。
- 题型卡：每个题型一张；吉米多维奇的题型在前，教材和吉米都没覆盖的在后并标「研」；例题优先选吉米或 30 讲的，写出处；通法只写这一类题的通用方法，不针对例题，附辅导书原话和出处，网页上可遮住；练习写书名、讲/章、印刷页、题号，吉米同类题号，苏大题集题号（恆告诉了再写），1000 题检验题号。
- 网页上不放「我的补充」，Markdown 存档留这一栏。
- 易错点：错误想法、陷阱小题和答案、为什么错、正确做法，注明关联的题型；尽量多挖。
- 页码以转换稿里的 `<!-- PDF第N页 · 印刷页M -->` 为准（标记后面的内容才属于印刷页 M）。
- 网页上不标「⚠️未核验」（2026-10-20）。没有出处的内容照样要求正确：计算先用代码验算，推导自己核对一遍，拿不准的不写进页面。
- 公式：行内 `$...$`，独立成行 `$$...$$`；不用 `\(` `\)` `\[` `\]`；`\left` `\right`、`\begin` `\end`、花括号要配对；矩阵用 `pmatrix`。
- 加粗的内容不以标点开头或结尾，标点放到星号外面。
- 数据字符串用 `String.raw`（`R\`...\``）写，反斜杠不用转义。
- 极限的 ε–N、ε–δ 定义不考，不放进页面。
- 「✎ 总结」只放恆自己的话：他口述的写进 `数据/我的总结.js`，原话照录；有不完整的地方在对话里指出，不替他改。

### 二、改完一定要做的检查

```
npm i katex            # 第一次
node gaoshu/工具/lint.js gaoshu/数据/第1章-第N节.js
```

lint 会逐条用 KaTeX 渲染公式，并检查 `$` 配对、旧分隔符、加粗的标点；输出 `problems 0` 才能提交。改了页面本身（`index.html`）的，还要在浏览器里实际点一遍：桌面和手机宽度（900 以下）各一次，看有没有报错。

### 三、发布流程

1. 改 `main` 分支，提交信息写清楚改了什么。推送后 Cloudflare Workers 自动部署（没有构建步骤，`wrangler.jsonc` 只指定 `assets.directory`）。
2. 同一份文件同步到学习仓库 `进度库/交互网页/高等数学/`（备份），并在 `进度库/决策记录/` 记一条、更新 `进度库/当前状态.md`。
3. `records` 分支只放个人记录（`state.json`、`review.md`、`wrong.json`），网页和克提交，不要和 `main` 合并。
4. 令牌只放在每台设备的浏览器里，不写进代码、不写进仓库、不发到聊天里。

### 四、改规则的规矩

- 改页面行为、数据格式、内容规则：先把方案告诉恆，他确认后再动手。
- 新规则当场写进本文件；和旧规则冲突时，以时间晚的为准。
- 数据格式有变化时，同步改上面的「加一节」和字段说明。
